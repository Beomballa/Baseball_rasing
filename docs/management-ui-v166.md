# V166 선수·관리 화면

2026-11-10에 승인된 두 번째 시안의 새 얼굴과 여섯 화면을 네이티브 SwiftUI에 연결했다. 디자인 시안 확인과 실제 앱 검증은 별도 기록한다.

## 화면별 변경

| 화면 | 적용한 내용 | 실제 값과 기존 동작 |
|---|---|---|
| 나의 선수 | 새 얼굴, 이름·역할·소속이 있는 선수 선택 카드와 선수 파일 | 선수별 달력을 구분해 현재 소속을 읽고 피로·행동·현재 일자를 표시한다. 목록 그리기에서는 소속 원장을 반복 검증하지 않는다. |
| 선수 생성 | 유형별 도트 표식·핵심 지표·능력 그래프, 외형 시작안 A~D, 최종 선수 카드 | 기존 능력 예산과 독립 외형 선택을 유지한다. 시작안 선택 후 세부 편집이 가능하며 최종 등록 명령은 그대로 사용한다. |
| 훈련장 | 준비 화면의 서 있는 선수 대신 선택 훈련의 도구·목표 도해와 다섯 번의 시도 표시 | 실제 선택 능력·구종·습득 중 여부를 사용한다. 훈련 시작·입력·중단·복구·확정 저장 경로는 유지한다. |
| 휴식 | 선수 얼굴과 피로 전후 막대, 회복량·행동·날짜 안내 | 실제 회복 예상값을 표시하며 취소는 저장하지 않는다. 회복 연출 뒤 기존 확정 저장 한 곳을 사용한다. |
| 스카우트실 | 선수 파일 표지, 확정 보고서 신원·표본·능력 막대·보유 구종 | 확정 자료는 저장 시점 외형과 능력을 사용한다. 현재 자료는 현재 소속을 사용하고 기존 탭·원문·프로젝트 연결을 유지한다. |
| 홈·경기장 | 현재 소속 구장의 원화·이름·로고를 메뉴에 연결하고 고정 스폰서 판넬을 제거 | 실제 경기에는 경기 시작 때 저장한 홈팀 구장을 사용한다. 팀 이동 후에도 과거 경기 구장을 현재 소속으로 바꾸지 않는다. |

## 원화와 저장 경계

새 관리용 초상은 머리 8종, 눈 4종, 눈썹 4종, 표정 6종과 기존 피부·머리 색을 조합한다. 원화 버전·독립 외형·구단·홈원정·역할·등번호를 포함한 키로 렌더를 재사용한다. 원본 선수 외형 필드와 저장 형식은 변경하지 않는다.

생성의 경기 동작 미리보기는 독립된 44pt 펼치기 버튼과 본문으로 나눈다. 펼친 제목의 접근성 영역이 본문의 다음 자세 버튼까지 포함하지 않게 하며, 자세 전환은 실제 경기 원화의 같은 경로를 사용한다.

큰 글자의 보고서는 파일 전용 선택 메뉴와 작은 선수 요약을 사용한다. 현재 자료의 선수명·기준일을 먼저 보여 주고, 확정 보고서의 전체 표지는 요약 탭에만 둔다. 다른 탭은 짧은 신원 다음에 본문이 이어진다. 생성 미리보기의 얼굴·경기 자세 설명도 같은 폭의 두 열에서 각각 줄바꿈한다.

훈련 진행 화면의 상·하단은 실제 콘텐츠 높이 변화를 직접 관찰한다. 준비 화면의 큰 측정값이 홈 이어하기에 남아 경기장을 최소 크기로 줄이는 경로를 제거하고, 같은 화면 크기에서 메뉴·홈 이어하기의 경기장 폭과 조작 가능 상태를 비교한다. 화면을 여는 순간의 폭이 0이어도 음수 경기장 프레임을 만들지 않는다.

홈 상단·선수 목록·생성 미리보기·휴식·보고서에 같은 관리용 초상을 사용한다. 실제 경기와 훈련의 투구·타격 모션 원화는 기존 승인본을 유지한다. 준비 화면의 정적 선수만 도해로 대체한다.

근접 경기장 배경은 기존 홈플레이트·마운드·타석 선과 원근을 유지하고 먼 관중석을 팀별 원화로 교체한다. 투수 시점의 심판은 잘림 없는 독립 원화로 합성한다. 좌우 카메라 반전과 공·존 좌표는 기존 장면을 그대로 사용한다.

## 검증과 배포 구분

검증은 사용자 저장과 분리된 QA 컨테이너 및 전용 시뮬레이터에서 수행한다. 실제 실행한 테스트·실패 보완·캡처·실행 명령은 로컬 QA 엑셀과 실행 기록에 보존한다. 화면 진입·읽기·취소 검사를 실제 경기 전체 진행이나 실기기 표시 성능의 통과로 기록하지 않는다.

이 변경은 새 TestFlight 업로드를 의미하지 않는다. 빌드 165의 과거 검증·배포 결과는 당시 기록으로 보존한다.
