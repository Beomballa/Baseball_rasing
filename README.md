# BM iOS

SwiftUI 선수 생성·홈, SwiftData 로컬 저장, 연간 일정·날짜 진행과 직접 타격/릴리스·경기 완료 원장·SpriteKit 연습장 진입을 연결한 iOS 프로젝트입니다. 기존 `../pitching-prototype` 웹과 독립된 Xcode 프로젝트입니다.

2026-10-20 교차 감사: [기능별 구현·검증 대조표](https://chatgpt.com/space/page_15beb5d31f60819186d121eea2f55c62)와 [다음 구현 우선순위](https://chatgpt.com/space/page_aa4282aede10819194c957a5ea8d66c8)를 기준으로 웹/네이티브/기획 상태를 구분합니다. 타격 포인트·타이밍/무입력 지켜보기·숙련도별 릴리스는 구현됐지만, 웹과 같은 아트·그립/수동 코스·변화구 궤적·타격/포수/수비 모션·훈련 성장·특성·리그/시즌·계약까지 이식한 상태는 아닙니다. 스피드/수비/송구는 저장·홈 표시만 있고 경기 판정에는 아직 전달하지 않습니다. 경기 피로 비용은 종료 때 저장하지만 시작 피로의 실행력 보정과 지구력 원본은 아직 없습니다. 신규 선수도 시연용 고정 초기값을 사용하므로 정식 고교 유형/예산을 적용했다고 표시하지 않습니다. 기존 저장은 새 예산으로 덮어쓰지 않습니다.

이번 감사에서는 기존 단위39+UI1=40개 통과 원자료와 현재 코드를 대조했습니다. 시뮬레이터/테스트를 다시 실행하거나 기존 세이브를 초기화하지 않았습니다. 아래 차수별 검증 수치는 해당 구현 시점의 이력이며 오늘 재실행 결과가 아닙니다.

## 환경

- iPhone / 세로 화면 / 최소 iOS 17.0
- Swift 6 언어 모드, Xcode 프로젝트와 공유 `BM` 스킴
- 첫 검증 도구: Xcode 27.1 (27A9275), Apple Swift 6.4, Simulator iOS 27.0. 최소 OS는 배포 타깃이며 iOS 17 실기기 검증 완료를 뜻하지 않습니다.
- SwiftUI / SpriteKit / SwiftData만 사용하며 외부 패키지·서버·로그인·CloudKit 연동이 없습니다.

`BM.xcodeproj`를 열고 `BM` 스킴과 iPhone Simulator를 선택해 실행합니다. 실기기는 Xcode의 Signing & Capabilities에서 자신의 Team과 고유 Bundle Identifier를 설정해야 합니다. 현재 `dev.bm.career`는 개발용 식별자이며 배포용 팀은 지정하지 않았습니다.

## 구현 범위

1. 이름(1~12자)·등번호(0~99), 고교50곳 직접/무작위 선택
2. 타자 포지션 / 투수 좌·우투, 6피부×6머리색×6유니폼×3머리형×3표정
3. 역할별 선수1명 저장, 다른 역할 추가와 홈 전환
4. 홈에서 소속·정보·실제 초기 능력/구종 숙련도·피로 확인
5. SpriteKit 도트 야구장 이동과 좌우 투구 손을 반영한 간단한 연습 장면
6. 가상 6팀·연 30경기 일정, 오늘 경기/상대·홈원정·다음 팀 경기·다음 개인 출전 확인
7. 16세·고1 / 2026-04-01 시작, 게임 달력 기념일에만 나이·학적 변경
8. 하루 휴식 1회, 다음 날 수면 회복, 최대 30일 회복 우선 묶음 진행·중지·일별 저장

연습장은 기록/성장/피로를 변경하지 않습니다. 공식 일정 경기는 휴식 → 오늘 경기 시작/이어하기 → 종료 결과 저장 → 홈의 다음 날 순서입니다. 미완료 경기는 날짜를 잠그며, 완료 원장이 저장된 경기일만 다음 날 버튼을 열어 수면 회복을1회 적용합니다. 비등판일에도 명시적으로 팀 경기를 진행하지만 개인 성적/경기 피로는 만들지 않습니다. 훈련/빠른 훈련·관찰 과제·특성·리그 순위/결산·계약은 후속 구현입니다.

### 달력 동작

- 선택 학교와 선수 UUID로 고정한 다른 5교가 가상 조별리그를 구성합니다. 50교 전국 순위를 계산하지 않습니다. 5라운드 원형 대진을 6회 반복하고 홈원정을 뒤집습니다. 매년 4월 1일부터 6일 간격, 9월 22일까지 팀당 30경기/리그 90경기이며 상대마다 홈 3·원정 3경기입니다.
- 타자는 매 경기 출전 예정, 투수는 팀 경기 1·6·11·16·21·26차전에 선발 예정입니다. 팀 일정과 개인 출전 일정을 구분합니다.
- 오늘 휴식은 피로 −18, 다음 날 수면은 −4이며 0~100으로 제한합니다. 행동 사용일/개정 번호를 저장해 휴식·이전 화면 입력의 중복 적용을 막습니다. 수면은 날짜를 실제로 바꿀 때만 적용합니다.
- 묶음 진행은 회복 우선만 제공합니다. 같은 하루 함수를 호출해 휴식+수면+날짜를 한 번에 저장하고 매일 취소 여부를 확인합니다. 이미 휴식한 날은 휴식을 다시 주지 않습니다. 경기일/나이 변경 직전이나 최대 30일에 멈춥니다. 훈련을 했다고 가정하거나 능력치를 올리지 않습니다. 균형 프리셋과 미구현 사건의 정지 조건은 해당 기능을 이식할 때 연결합니다.
- 나이는 시작일의 기념일 기준입니다. 새 선수는 2027/2028년 4월 1일에 고2/고3, 2029년은 19세·졸업/진로준비, 2030년은 20세·성인 진로 선택 대기입니다. 묶음 진행은 변경일 직전에 멈추고 하루 진행의 확인 후 전환합니다. 시즌 종료·기기 시계·재실행으로 나이가 바뀌지 않습니다. 19세 이후 고교 경기를 만들거나 프로·대학 소속을 자동 배정하지 않습니다.
- 30차전도 종료 원장을 저장하고 날짜를 진행할 수 있습니다. 30경기 결산과 다음 시즌 개방 화면은 아직 없으며, 현재 경기 기록은 연도가 바뀌어도 삭제하지 않습니다.

## 구조와 저장

- `BM/App`: 초기 데이터 로드/오류·재시도, NavigationStack·역할 선택
- `BM/Domain`: 선수 생성 검증·역할/외형·학교 데이터 계약
- `BM/Persistence`: V1 선수/V2 달력 모델 보존·V3 경기 원장 추가, 로컬 전용 Container, 날짜 진행·명시 저장과 실패 rollback
- `BM/Features`: 생성·홈·경기장 화면
- `BM/UI`: 도트 캐릭터·각진 버튼·정보 패널/수치 막대
- `BM/Resources/schools.json`: 기존 확정50교 ID/지역/이름. 학교·공식 자산 이용 허락을 의미하지 않습니다.
- `BMTests`: 입력 검증·역할 분리/중복 거부·실제 파일 재열기와 외형/구종 보존
- `BMUITests`: 전용 빈 시뮬레이터에서 생성→재실행→경기장→두 번째 역할→재실행 흐름

SwiftData의 CloudKit/group container를 명시적으로 끄고 자동 저장도 끕니다. 생성 성공은 `context.save()` 후에만 홈으로 전환합니다. 저장소를 열지 못하면 오류와 재시도를 제공하며 자동 삭제/메모리 저장으로 대체하지 않습니다. 사용자가 데이터를 지우거나 앱을 삭제하면 복원을 보장하지 않습니다. 웹 localStorage를 읽거나 이전하지 않습니다.

## 검증

Xcode의 Product → Test 또는 다음 명령으로 실행합니다. UI 테스트는 신규 선수 생성을 검증하므로 **전용 빈 시뮬레이터**를 사용합니다. 테스트 코드에는 사용자 세이브 초기화 기능이 없습니다.

```sh
xcodebuild -project BM.xcodeproj -scheme BM -destination 'platform=iOS Simulator,id=<전용 기기 UDID>' -derivedDataPath /tmp/BM-iOS-DerivedData CODE_SIGNING_ALLOWED=NO test
```

V1→V2 경량 마이그레이션으로 달력 테이블만 추가합니다. 선수/구종 모델은 바꾸지 않으며 ID·학교·이름/번호·외형/손·능력치/숙련도·피로·저장 날짜를 유지합니다. 기존 선수는 그 저장 날짜를 나이 진행 기준일로 한 번 고정하고 기존 저장 표시를 붙입니다. 과거 경기 결과·행동 이력·프로 계약을 생성하지 않습니다. 신규/기존 선수 모두 달력을 명시 저장하며 재실행으로 조별리그가 재추첨되지 않습니다.

실제 V1 SQLite 파일 생성→현재 Container로 열기→두 역할/구종 보존→비경기일 진행→재열기를 테스트합니다. 전체 커리어·실제 디스크 고장·계약 엔진 검증은 이번 범위가 아닙니다. 저장 경계 오류 주입은 아래 달력 오류 보강에서 검증했습니다.

## Git

이 `ios` 폴더를 독립 저장소 경계로 사용합니다. 웹 실험물·대용량 QA·사용자 환경 설정과 앱 출시 이력을 분리합니다. 공유 스킴/소스/학교 JSON/테스트는 관리하고 DerivedData·개인 Xcode 설정·서명 파일은 제외합니다. 사용자가 지정한 GitHub 원격에 연결하고 최초 테스트 커밋을 올립니다. 이후 기능 단위 개발을 마치고 관련 검증을 통과할 때마다 커밋/push합니다. 제목은 `YYYY.MM.DD 구체적인 기능 작업 수행` 형식이며 작업일은 KST 기준입니다.

기획 정본은 `../pitching-prototype/docs/`의 MVP/일정/경기·육성 설계/구현 현황을 따릅니다. 이 README는 현재 네이티브의 구현 경계를 설명하며 전체 기획을 복제하지 않습니다.

## 소스 업로드와 개인정보 보호

기존 Java 프로젝트의 제외 정책을 검토해 소스 내부 숨김 도구 폴더·자동 생성 코드·IDE 모듈 설정·SQL 제외를 보완했습니다. 해당 프로젝트의 Gradle/Java 규칙, Markdown 전체 제외, 테스트 제외는 iOS에 복사하지 않습니다. 개발 규칙·공유 훅·테스트 코드는 유지합니다.

업로드 대상은 Swift 앱/테스트, 공유 Xcode 프로젝트/스킴, 학교 JSON, 검토한 번들 도트 아트 9개, Git 검사 스크립트, README/개발 규칙입니다. 도트 아트는 명시 경로와 SHA-256으로 제한합니다. 테스트 결과·스크린샷·로그·세이브·개인 IDE 설정·환경 파일·인증/서명 파일은 로컬에만 둡니다. QA 경로를 설명하는 문서가 있어도 해당 산출물은 원격에 포함되지 않습니다.

일반 Bundle Identifier와 Xcode 내부 참조ID는 빌드에 필요한 공개 가능한 설정이며 비밀키가 아닙니다. 개인 Team/인증값은 공유 프로젝트에 입력해 커밋하지 말고 `Signing.local.xcconfig` 등 로컬 설정으로 관리합니다. `.gitignore`만으로 이미 추적하거나 강제 추가한 파일을 보호할 수 없어 pre-commit에서 staged 파일을 다시 검사합니다. 패턴 검사는 완전한 비밀 탐지 도구가 아니므로 staged diff 검토도 수행합니다.

최초 clone 후 로컬 훅을 활성화합니다. 작성자는 자신의 GitHub noreply 주소를 저장소 로컬 설정에 사용합니다. 이 값과 원격 인증정보는 추적 파일에 저장하지 않습니다.

```sh
git config core.hooksPath .githooks
python3 scripts/test_git_security.py
python3 scripts/check_staged.py
```

커밋 메시지 예: `2026.10.19 iOS 선수 생성 및 로컬 저장 작업 수행`. 기능 완료 후 테스트/빌드·staged 개인정보 검사·push·원격 SHA 확인을 수행합니다. 자동 시간 스케줄이 아니라 이 저장소의 개발 작업 규칙입니다.


## 2026-10-19 수치 표시와 날짜 전환

- 능력치/구종 숙련도는 소수점1자리로 표시한다. 모델 값·저장 스키마·성장 계산은 반올림하지 않는다.
- 하루 진행/연습장 진입 시 도트 달력과 날짜를 짧게 보여준다. 묶음 진행은 하루 저장에 성공한 날짜만 표시하고 약100ms 간격으로 넘긴다. 날짜·수면 회복의 기존 저장 함수는 그대로 사용한다.

## 2026-10-20 경기 화면·도트 연출 이식
