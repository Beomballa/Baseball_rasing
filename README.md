# BM · Baseball Career

**고교에서 시작하는 나만의 야구 선수 커리어**

타자와 투수, 훈련과 실전, 성장과 계약을 연결하는 iOS 도트 야구 게임입니다.

구장 배경 리소스입니다. 선수·공·전광판은 경기 중 별도 레이어로 표시합니다.

<a id="overview"></a>
## 어떤 게임인가요?

16세 고교 선수로 시작해 직접 경기를 뛰고, 훈련과 경기 성적으로 성장하는 개인 커리어 게임입니다. 스카우트 관찰과 평가를 거쳐 국내·해외 진로와 계약으로 이어집니다.

**선수 생성 → 훈련·휴식 → 공식 경기 → 성장·기록 → 다음 일정**

| 항목 | 현재 기준 |
|---|---|
| 플랫폼 | iPhone · 세로 화면 · iOS 17 이상 |
| 조작 | 타자 스와이프 조준·탭 타격 / 투수 구종·코스 선택·릴리스 게이지 |
| 표현 | SwiftUI 정보 화면 + SpriteKit 도트 경기 연출 |
| 저장 | SwiftData 로컬 저장 · 서버·로그인·CloudKit 없음 |
| 개발 상태 | 기능 구현과 검증 진행 중 |

이 저장소는 iOS 네이티브 프로젝트입니다. 별도 웹 프로토타입과 전체 기획은 공개 소스 배포물에 포함하지 않습니다.

<a id="features"></a>
## 지금 플레이할 수 있는 기능

| 영역 | 구현한 내용 |
|---|---|
| 선수 생성·홈 | 고교 50곳 선택·무작위 배정, 타자·투수, 이름·등번호·외형·포지션·투구 손, 유형과 직접 능력치 배분. 등록 전에 선택한 조건을 확인합니다. 클럽하우스에서 홈 구장, 시설, 오늘 할 일을 확인할 수 있습니다. |
| 훈련·성장 | 능력별 훈련, 구종 습득·숙련, 특성·포지션 훈련, 실전 XP, 피로·휴식·하루 행동 제한을 적용합니다. 제구 훈련은 결과를 확인한 뒤 다음 시도 준비까지 자동으로 넘길 수 있습니다. |
| 직접 경기 | 타자는 스와이프로 조준해 타격하고, 투수는 구종·코스와 릴리스를 조작합니다. 경기 자동 진행은 다음 내 타석, 다음 내 등판 이닝, 경기 종료 중 선택할 수 있습니다. |
| 수비·주루와 하이라이트 | 뜬공 추격, 외야 백업·베이스 커버, 병살·태그업·실책과 베이스 포구를 표시합니다. 결과 화면에서 홈런과 수비·주루 장면을 다시 볼 수 있습니다. |
| 경기·훈련 연출 | 경기와 훈련의 공통 투구 모션, 타격·포구 효과음, 심판 콜·한국어 자막, 음량 설정과 접촉 진동을 사용합니다. |
| 구단·구장 | 가상 KBO 10팀·NPB 15팀·MLB 15팀의 홈·원정 유니폼 80벌과 고교·프로 홈 구장 90곳을 사용합니다. 같은 구장의 잔디와 관중석은 투구·타격, 인플레이, 하이라이트에서 이어집니다. |
| 일정·시즌 | 팀당 연 30경기, 선발 로테이션, 순위·성적·시즌 결산을 제공합니다. 일정 자동 진행은 경기, 관찰과 계약 평가, FA 선언 안내 등 확인할 일이 생기면 멈춥니다. |
| 기록·시상 | 커리어 일지에서 저장된 경기·훈련·스카우트·계약을 날짜순으로 엽니다. 시즌 결산과 일지에서 개인 타이틀, 올해의팀, 골든글러브의 결과와 보류 사유를 확인합니다. |
| 관찰·출전 경쟁 | 28일 관찰 보고서, 구단 관심, 포지션 적합도·코치 추천, 주전·벤치·선발 순번과 다음 평가를 확인합니다. |
| 국내·해외 계약 | 고교·대학·육성·1군 경로, 제의·재계약·방출·재입단과 FA 시장을 지원합니다. 계약서는 당시 구단 로고, 역할, 계약 기간, 연봉지수·계약금을 보여줍니다. |

대학과 미국 조직 육성 리그는 6팀 편성입니다. 기존 저장의 진행 중인 시즌에는 당시 편성을 적용합니다. 확장 리그의 순번과 저장 복원은 [구현·검증 이력](docs/implementation-history.md#portland-pitcher-rotation)에서 확인할 수 있습니다.

해외 계약·FA·30경기 시즌은 가상 구단을 사용하는 게임 정책입니다. [계약과 FA 적용 기준](docs/implementation-history.md#overseas-fa-in-season)을 참고할 수 있습니다.

<a id="getting-started"></a>
## 실행하기

### 1. 프로젝트 열기

```sh
git clone https://github.com/Beomballa/Baseball_rasing.git
cd Baseball_rasing
open BM.xcodeproj
```

Xcode에서 공유 **BM** 스킴과 iPhone Simulator를 선택해 실행합니다. Swift 6 언어 모드, 최소 배포 타깃 iOS 17.0을 사용합니다. 최소 배포 타깃은 해당 OS에서의 검증 완료를 뜻하지 않습니다.

### 2. 실기기에서 실행하기

`Signing & Capabilities`에서 자신의 Team과 고유 Bundle Identifier를 설정합니다. 서명·프로비저닝·개인 Xcode 설정은 공유 소스에 포함하지 않습니다.

기존 선수가 있는 기기에서는 별도 QA 앱·저장 공간을 사용합니다. QA를 위해 기존 앱을 삭제하거나 사용자 저장을 초기화하지 않습니다.

### 일반 앱과 QA 앱 구분

| 실행 스킴 | 아이콘 | 앱 이름 | 용도 |
|---|---|---|---|
| BM · Debug/Release | 낮 구장의 타자 스윙 | 픽셀야구인생 | 일반 플레이 |
| BM-QA · QA | 노을 구장의 투수·금색 QA | BM 성능 QA | 별도 저장에서 검증 |

두 앱은 기존 Bundle ID로 함께 설치할 수 있습니다. QA에는 **BM-QA** 스킴을 사용합니다. Bundle ID만 바꾸면 QA 아이콘 구성이 적용되지 않습니다.

### 3. 기본 플레이 흐름

1. 선수를 생성하고 능력치·구종·일정을 확인합니다.
2. 오늘의 훈련 또는 휴식을 선택합니다.
3. 경기일에는 오늘 경기를 시작하거나 이어서 진행합니다.
4. 경기 종료·결과 저장 후 홈에서 다음 날로 넘어갑니다.

미완료 경기는 날짜 진행을 잠급니다. 자유 연습은 실제 성장·기록·날짜·피로에 반영하지 않습니다.

## 기술과 코드 구조

| 기술 | 역할 |
|---|---|
| SwiftUI | 선수 생성·홈·훈련·계약·기록 화면, 경기 조작부 |
| SpriteKit | 투구·타격·수비·주루와 도트 선수·공·경기장 렌더링 |
| SwiftData | 선수·일정·경기·훈련·관찰·계약 저장과 마이그레이션 |
| XCTest / XCUITest | 규칙·저장·중복 반영 방지·화면 흐름 검증 |

```text
BM/
├── App/           앱 시작 · 저장소 연결 · 화면 진입
├── Domain/        선수 · 경기 · 훈련 · 일정 · 계약 규칙
├── Persistence/   SwiftData 모델 · 저장 명령 · 마이그레이션
├── Features/
│   ├── Creation/  선수 생성
│   ├── Home/      선수 홈 · 커리어 정보
│   ├── Match/     경기 조작 · 인플레이 · 결과 연출
│   └── Training/  능력 · 구종 · 특성 · 포지션 훈련
├── UI/            공통 도트 UI · 패널 · 버튼
└── Resources/     학교 데이터 · 검수한 게임 아트
BMTests/           단위 · 저장 회귀 테스트
BMUITests/         화면 흐름 테스트
scripts/           Git 개인정보 검사 · 검증 보조 도구
```

### 저장할 때 지키는 원칙

- **SwiftData V15** — 기존 선수 ID·구종·원장을 이전하고 은퇴 선수를 보존합니다. 활성 선수는 역할별 1명으로 제한하며, 파일 이전 전에 DB 구성 파일을 별도 백업합니다.
- **명시 저장·실패 복구** — 자동 저장을 끄고 사건 단위로 저장합니다. 실패 시 오류·재시도를 제공하며 저장소를 자동 삭제하거나 임시 저장으로 전환하지 않습니다.
- **이어하기·1회 반영** — 경기·훈련의 진행 원장과 보상을 보존합니다. 다시 보기와 렌더링에서 새 판정·보상을 만들지 않습니다.
- **고정 근거** — 날짜·나이·피로·하루 행동, 28일 보고서·평가 창을 각 원장 규칙으로 관리합니다. 과거 미수집 기록을 추정해 채우지 않습니다.

<a id="verification"></a>
## 검증 상태

규칙·저장은 XCTest, 실제 화면 흐름은 XCUITest로 검증합니다. 실행별 커버리지와 시뮬레이터·실기기·배포 검증의 범위는 [구현·검증 이력](docs/implementation-history.md#follow-up-verification-2026-11-17)에 기록합니다.

공유한 **BM-QA** 스킴은 일반 앱과 별도인 저장 공간을 사용합니다. 다음 명령은 설치된 시뮬레이터를 선택한 뒤 실행합니다.

```sh
xcrun simctl list devices booted
xcodebuild -project BM.xcodeproj -scheme BM-QA -destination 'platform=iOS Simulator,id=<SIMULATOR_ID>' CODE_SIGNING_ALLOWED=NO test
python3 -m unittest discover -s scripts -p 'test_*.py'
```
